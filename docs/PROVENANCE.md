# Model, dataset and dependency provenance

The problem statement asks participants to declare the origin and licence of every pretrained model and dataset.
This file is that declaration. "Used" means it produced the numbers in `docs/EVALUATION_REPORT.md`;
"supported" means the code path exists but was not exercised in our build; "planned" means not yet built.

## 1. Models

| Model | Status | Origin | Licence | Notes |
|---|---|---|---|---|
| `drishti-lite-spectral-v1` | **Used** (all reported results) | Written by Team Error_404$ (`drishti/embed.py`) | MIT (this repo) | No pretrained weights; hand-designed concept + visual features, 52-d |
| RemoteCLIP ViT-B/32 | **Supported, not executed** | Liu, Chen et al., *RemoteCLIP: A Vision Language Foundation Model for Remote Sensing*, IEEE TGRS 2024, arXiv:2306.11029. Code: github.com/ChenDelong1999/RemoteCLIP. Weights (OpenCLIP format): Hugging Face `chendelong/RemoteCLIP` | Listed as Apache-2.0 by its public release; **re-verify the licence shipped with the exact checkpoint before deployment** (we could not download it in our build environment) | Trained by its authors on RSITMD, RSICD, UCM-Captions and remote-sensing detection / segmentation data converted to captions. Developed outside India |
| OpenCLIP (model code / tokenizer) | Supported | github.com/mlfoundations/open_clip | MIT | Used only to instantiate the RemoteCLIP architecture |
| Prithvi-EO-2.0 | Planned alternative | NASA & IBM, arXiv:2412.02732 | Apache-2.0 (per release) | Candidate replacement embedder |
| In-house self-supervised encoder | Planned alternative | To be trained on Sentinel-2 / Bhuvan tiles following the SSL4EO-S12 recipe (arXiv:2211.07044) | Owned by the deployer | Removes dependence on foreign-origin weights |

**Safeguards implemented for any pretrained checkpoint** (`RemoteCLIPEmbedder`): weights are read only from the
local `models/` folder; a `<checkpoint>.sha256` pin file must exist and match or loading is refused; loading uses
`torch.load(..., weights_only=True)` so no pickled code is executed; the checkpoint hash prefix is recorded as the
model fingerprint in every scene's processing provenance. There are no runtime downloads.
